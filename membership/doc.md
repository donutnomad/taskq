## 设计说明

membership 包的定位                                                                                                                                                                                                   
                                                                                                                                                                                                                        
  membership 包不做消息转发。它的职责非常单一：                                                                                                                                                                         
                                                                                                                                                                                                                        
  1. 成员发现 — 每个节点通过 DB 心跳注册自己，通过轮询 DB 发现其他节点                                                                                                                                                  
  2. 一致性哈希路由 — Lookup(key) 告诉你"这个 key 应该由哪个节点负责"                                                                                                                                                   
                                                                                                                                                                                                                        
  它不负责节点间通信、请求转发、数据同步——这些是上层业务的事。调用方拿到 Lookup 返回的地址后，自己去建 gRPC 连接做 RPC 调用。                                                                                           
                                                                                                                                                                                                                        
  消费者-分区绑定的设计                                                                                                                                                                                                 
                                                                                                                                                                                                                        
  你的理解大体正确，但有几个关键细节需要澄清：                                                                                                                                                                          
                                                                                                                                                                                                                        
  正确的部分                                                                                                                                                                                                            
                                                                                                                                                                                                                        
  - 用 Lookup(partitionKey) 算出"谁应该拥有这个分区"                                                                                                                                                                    
  - 用 DB 租约（lease）作为实际的所有权凭证                                                                                                                                                                             
  - 节点下线 → 心跳停止 → 哈希环重算 → 新节点接管                                                                                                                                                                       
                                                                                                                                                                                                                        
  需要修正的部分                                                                                                                                                                                                        
                                                                                                                                                                                                                        
  "其他没分配到的就一直竞争拿"——不完全是这样。                                                                                                                                                                          
                                                                                                                                                                                                                        
  正常情况下不需要竞争。所有节点用相同的哈希函数 + 相同的成员列表，所以 Lookup 的结果是确定性的——大家都同意"分区 X 属于节点 A"。流程是：                                                                                
                                                                                                                                                                                                                        
  1. 节点 A 算出 Lookup("partition-X") == 自己                                                                                                                                                                          
  2. 节点 A 去 DB 拿 lease → 成功，开始消费                                                                                                                                                                             
  3. 节点 B 算出 Lookup("partition-X") == 节点 A（不是自己）                                                                                                                                                            
  4. 节点 B 不会去抢这个 lease                                                                                                                                                                                          
                                                                                                                                                                                                                        
  竞争只发生在成员视图不一致的窗口期（因为各节点独立轮询 DB，视图有 pollInterval 的延迟差）：                                                                                                                           
                                                                                                                                                                                                                        
  1. 节点 A 下线                                                                                                                                                                                                        
  2. 节点 B 先轮询到变化，算出 Lookup("partition-X") == 自己，去拿 lease                                                                                                                                                
  3. 节点 C 还没轮询到，也算出 Lookup("partition-X") == 自己，也去拿 lease                                                                                                                                              
  4. 但 DB lease 保证只有一个能拿到 → 这就是 lease 的价值                                                                                                                                                               
                                                                                                                                                                                                                        
  推荐的架构                                                                                                                                                                                                            
                                                                                                                                                                                                                        
  ┌─────────────────────────────────────────┐                                                                                                                                                                           
  │            你的分区管理器                  │                                                                                                                                                                        
  │                                         │                                                                                                                                                                           
  │  1. 监听 ChangedEvent（成员变化）           │                                                                                                                                                                       
  │  2. 遍历所有分区，Lookup 判断是否属于自己     │                                                                                                                                                                     
  │  3. 属于自己的 → 尝试获取 DB lease          │                                                                                                                                                                       
  │  4. 拿到 lease → 启动消费者               │                                                                                                                                                                         
  │  5. 不属于自己的 → 释放 lease + 停止消费者   │                                                                                                                                                                      
  │                                         │                                                                                                                                                                           
  │  哈希环 = 建议权（谁应该拥有）               │                                                                                                                                                                      
  │  DB lease = 决定权（谁真正拥有）            │                                                                                                                                                                       
  │  两者结合 = 高效 + 安全                    │                                                                                                                                                                        
  └─────────────────────────────────────────┘  
关键设计原则：                                                                                                                                                                                                        
                                                                                                                                                                                                                        
  - 哈希环是优化手段：避免所有节点都去抢所有 lease，减少 DB 竞争                                                                                                                                                        
  - DB lease 是安全保证：解决视图不一致窗口期的 multi-owner 问题                                                                                                                                                        
  - 当前实现只有 DB lease + RangeID CAS，还没有 fencing token 这一层保护                                                                                    
  

各场景总结                                                                                                                                                                                                            
                                                                                                                                                                                                                        
  ┌─────────────────────────┬─────────────────────────────────────────────────┬──────────┐                                                                                                                              
  │          场景           │                    最大延迟                     │ 平均延迟 │                                                                                                                              
  ├─────────────────────────┼─────────────────────────────────────────────────┼──────────┤                                                                                                                              
  │ 节点加入                │ pollInterval（5s）                              │ ~2.5s    │                                                                                                                              
  ├─────────────────────────┼─────────────────────────────────────────────────┼──────────┤                                                                                                                              
  │ 优雅下线（EvictSelfAt） │ pollInterval（5s）                              │ ~2.5s    │                                                                                                                              
  ├─────────────────────────┼─────────────────────────────────────────────────┼──────────┤                                                                                                                              
  │ 节点崩溃                │ heartbeatCutoff + pollInterval = 20s + 5s = 25s │ ~22.5s   │                                                                                                                              
  └─────────────────────────┴─────────────────────────────────────────────────┴──────────┘                                                                                                                              
                                                                                                                                                                                                                        
  崩溃场景详细时间线                                                                                                                                                                                                    
                                                                                                                                                                                                                        
  T=0s     节点 A 最后一次心跳写入 DB                                                                                                                                                                                   
  T=10~15s 节点 A 本该发下一次心跳，但已崩溃                                                                                                                                                                            
  T=20s    心跳过期（healthyHostLastHeartbeatCutoff=20s）                                                                                                                                                               
           此时 GetActiveMembers 不再返回节点 A                                                                                                                                                                         
  T=20~25s 其他节点下一次 pollLoop tick 读到变化                                                                                                                                                                        
           ──────── 最终感知到节点 A 已下线 ────────                                                                                                                                                                    
                                                                                                                                                                                                                        
  关键参数   
  heartbeatLoop 间隔:  10s + rand(0~5s)    // monitor.go:313                                                                                                                                                            
  healthyHostLastHeartbeatCutoff: 20s       // monitor.go:17                                                                                                                                                            
  pollInterval: 调用方传入（example 中是 5s）  // monitor.go:209                                                                                                                                                        
                                                                                                                                                                                                                        
  20s 的 cutoff 刚好覆盖最大心跳间隔 15s，留了 5s 余量防止网络抖动或 DB 延迟造成误判。如果你需要更快的故障检测，可以缩短心跳间隔和 cutoff，但要注意 DB 写入压力会相应增大。
